service user

   12. create the service user agent, hidden, not an administrator (to do, recorded not run under --prefix)
       $ dscl . -create /Users/agent
       $ dscl . -create /Users/agent UserShell /bin/zsh
       $ dscl . -create /Users/agent RealName 'sirven agent'
       $ dscl . -create /Users/agent UniqueID 601
       $ dscl . -create /Users/agent PrimaryGroupID 20
       $ dscl . -create /Users/agent NFSHomeDirectory <prefix>/Users/agent
       $ dscl . -create /Users/agent Password '*'
       $ dscl . -create /Users/agent IsHidden 1
       $ dscl . -create /Users/agent GeneratedUID "$(uuidgen)"   # only when the directory service gave none

transport: tailscale
   25. write the tailnet policy snippet (to do)
       # write <prefix>/etc/sirven/tailscale-policy-snippet.hujson (mode 0644): tag:agent, reachable only from your login, only on port 22
   26. paste the policy snippet into your tailnet policy (owner, by hand)
       tailscale admin console, access controls: merge /etc/sirven/tailscale-policy-snippet.hujson and put your login in place of you@example.com.
   27. give the installer one tagged auth key, once (owner, by hand)
       tailscale admin console, settings, keys: generate an auth key with tag:agent, pre-approved. ephemeral is the better choice: the node then leaves the tailnet by itself when it logs out.
       hand it over one of two ways, and it is the only interactive step:
         in a file, the safer way and the one to use first: save it as /etc/sirven/tailscale-auth-key, owned by root, mode 0600, with one name only (no hard link) and no extra access control list; it is removed after the join. this is the only way that never puts the key in an environment.
         in the environment: set SIRVEN_TAILSCALE_AUTHKEY (or TAILSCALE_AUTHKEY) in your shell and run sudo --preserve-env=SIRVEN_TAILSCALE_AUTHKEY. sudo allows that only when its policy does: a sudoers rule for all commands implies the SETENV tag, a narrower rule needs that tag, or an env_keep line for the variable. when the policy does not allow it, sudo may refuse the command with an error; without the option, sudo drops the variable and the join finds no key. the installer takes the key out of its environment at once and hands it only to the join, but it cannot scrub the block of the environment it was started with: root can still read it in /proc/<installer process number>/environ until the installer ends.
   28. join the tailnet as a tagged device with that key (plan only)
       $ tailscale up --auth-key=file:<a private copy of the key> --advertise-tags=tag:agent --hostname=agent-<this machine's name> --ssh=false --accept-dns=false --accept-routes=false --reset
       not yet: applying to a macos machine is not verified yet; the join runs only on linux, inside a throwaway container
     note: the agent client connects with: ssh agent@<this machine's tailnet name>. tailscale ssh stays off; the machine's own SSH server and keys are used.
